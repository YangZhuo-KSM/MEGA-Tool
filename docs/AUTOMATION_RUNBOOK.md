# MEGA_Tool 自动扩充运行规则

更新时间：2026-10-21，Asia/Hong_Kong。

## 目标

在不占满用户额度的前提下，持续扩充巴黎手稿德中对应数据。每个5小时窗口为用户保留约30%—40%，同时保护旧正文、ID、人工确认、来源映射、reviews字节和已冻结的抽样建议。

## 每轮入口

每次定时任务使用独立新对话并直接操作本地项目 `C:/MEGA_Tool`。开始任何修改前依次读取：

1. 全局 `C:/Users/szyz2/.codex/AGENTS.md`；
2. `Scope.md`、`To_do.md`、`Status.md`、`project_handoff.md`；
3. `PLAN.md`、`docs/DATA_MODEL.md`、`docs/CODE_GUIDE.md`；
4. 本文件与 `docs/AUTOMATION_LESSONS.md`。

随后核对实际数据、源文件、版本、已执行批次和工作区改动。状态摘要只用于定位，实际文件决定现状。已执行批次禁止重跑。

## 额度门槛

每轮开始、每批写入并完成保护审计后、收尾前读取当前账户额度：

- 5小时已用不高于50%：允许开始新的标准批次；
- 5小时已用51%—54%：不开始24组标准批次，只允许完成已经开始的完整句群；
- 5小时已用达到55%：停止新增正文，转入保护审计、状态同步和必要收尾；
- 5小时已用达到65%：硬停止。只确认四份恢复文件已经保存，不再运行耗时操作；
- 周额度已用达到70%：停止自动扩充，保存状态后等待额度恢复；
- 额度不可读取或字段含义不明确：不猜测、不新增，记录原因后退出。

单次运行最多完成3个批次。每批约24组，可为完整句群或章节边界小幅调整。开始新批次前同时满足额度门槛与批次上限。

## 上下文与交接

独立定时任务每次运行均创建新对话，使用本地状态恢复，不传递整段历史聊天。若运行中可读取上下文容量，达到70%立即同步并结束；无法读取准确百分比时，用每轮最多3批作为主动上限。

每次修改或完成一项工作后，在继续下一项前同步有变化的文件：

- `Scope.md`：目标、边界、交付与验收；
- `To_do.md`：剩余事项和下一条可执行步骤；
- `Status.md`：唯一当前快照、证据、额度、产物、阻塞；
- `project_handoff.md`：新对话最短恢复入口。

状态记录包含运行时间与时区、运行前后5小时及周额度、执行批次、修改文件、验证结果、下一起点。额度只记录工具真实返回值。

阶段性同步可使用 `python scripts/checkpoint_automation.py --phase "实际阶段" --next "下一操作" --quota "5小时已用%/周已用%"`：自动读实际JSON计数，在四文件同一标记块更新并回读。额度参数必须来自最近工具实读；抽样未延续或审计未完成要写入phase，不能把计数更新当作验证通过。收尾再整理一致的当前快照。

## 扩充与验证

- 优先从 `To_do.md` 的连续推进队列执行，批号与起点只在四份恢复文件维护；不得使用本文中的历史批号决定重跑。
- 常规提取复用本地脚本和缓存；逐页检查实际来源图像；LLM用于疑难片段。
- 新对应默认 `uncertain`；扫描校订不能计作用户人工确认。
- 每批运行写入前只读验证、写入后保护审计及受影响测试。
- 每条命令检查实际exit_code与结果后才执行下一写操作或记录成功。任一审计/抽样命令非零时立即保存四恢复文件并停止，禁止在同一未设失败门禁的调用中预排后续追加。
- 抽样冻结包含疑点完整元数据（包括evidence_pages）。跨页疑点应在首次抽样前显式定位实际页；冻结后即使仅改证据页也会改变scope_digest，须先形成可审计迁移/勘误方案，不能强制重建或静默改指纹。
- 已授权的342→343单项修复见scripts/repair_sampling_evidence_page.py及local_backups/sampling-evidence-migration-20261021/migration.json。脚本默认只读，只有把该页恢复旧值后恰好匹配原digest才允许迁移；建议和其他字段原样保留，正常抽样保护不变。不得把它当作通用忽略失配或强制重建入口。
- 逐页对照正文数字与边栏行号；source_slices.stream会过滤行首1—2位数，遇正文数量必须在配方中依扫描显式恢复并只读断言（如第38批德343页首20）。
- 第31批起可使用 `python scripts/audit_incremental_batch.py <批号>` 对照对应配方及写入前备份，检查旧记录/指纹/提取证据/来源映射/reviews字节和冻结抽样；报告保存在tmp。不要运行旧批次追加脚本来“验证”。
- 默认不跑全量测试。只有发布里程碑、跨模块行为变化或定向验证暴露具体疑点时扩大测试。
- 不修改原PDF，不运行强制抽样重建，不静默修正疑似底本字形。
- 不commit、不push、不发布GitHub，除非用户另行授权。
- 源码包和Windows包只在阶段性发布节点或用户指定时更新，不逐批打包。

## 经验改进

每轮收尾检查是否出现可复用的新经验。只有存在实际证据时才更新 `docs/AUTOMATION_LESSONS.md`，采用“症状—触发条件—原因或假设—有效修复—验证—适用范围”结构，并合并同义项。

允许在当前项目内改进重复性脚本、断言和流程说明。修改方法时在 `Status.md` 记录理由和验证。全局配置、全局记忆及其他项目不在此自动化授权范围内。

## 停止和通知

遇到以下任一情况，保存状态并停止：

- 来源无法可靠辨认或德中对应需要用户判断；
- 保护审计失败，且最小修正后仍无法恢复；
- 工作区出现无法确认所有权的交叉改动；
- 需要提交、发布、删除用户材料或扩大到其他项目；
- 项目达到既定完整范围。

有新增成果、失败或需要用户决定时通知用户；仅因额度门槛未运行且状态无变化时保持安静。项目完成后暂停本自动化。
